# 連札(Renfuda)開発メモ(v0.5 まで)

> 公開向けの説明はリポジトリ直下の README.md にあります。このファイルは試作の各段階で記録した開発メモです。仕様書は `docs/spec/` にあります。

RenkuOS 用のカード型データベースの試作です。v0.4 までは「BDB」という名前でした。v0.5 で名前を「連札(Renfuda)」に、拡張子を `.bdb*` から `.rfd*` に変えました(下の「v0.5 の変更」)。v0.2 では、次の追加仕様に対応しました。

- `card-db-spec-v0.4.md`(データ形式と保存層)
- `card-db-ui-spec-v0.3.md`(UI)
- `card-db-theme-spec-v0.1.md`(テーマ、アイコン、BeOS らしさ)
- `card-db-io-spec-v0.1.md`(リンク、CSV 取り込み、PDF 出力)

v0.1(spec v0.2 / UI v0.1)のソースは `../bdb-v0.1-backup-20261015.tar.gz` に退避してあります。

**UI は、RenkuOS の VM(virt-manager、2026-10-17 の RenkuOS ソース)で主な操作を確認しました**(下の「VM での確認」)。`core` は Linux 上のテストで確認しています。

  PaperWindow  用紙サイズと向き(プレビューつき)

## ビルド

```sh
make test      # core の受け入れテスト(Linux 上)
make bench     # 10 万枚の計測(build/bench に約 400 MB)
make csvbench  # 10 万行の CSV 取り込みの計測
make data      # プリセット・サンプル・テーマ・変換表を作り直す
make app       # RenkuOS 向けクロスビルド → build/haiku/BDB/BDB
make package   # アプリ+同梱データ → build/haiku/BDB.zip
make hpkg      # パッケージ → build/bdb-0.2.0-1-x86_64.hpkg(pkgman install ./bdb-*.hpkg)
```

- クロスビルドは `~/renku/generated` を使います。リンクに、netservices(`libnetservices.a`、`libshared.a`、`libbnetapi.so`)と zlib(Haiku の基本パッケージに含まれる `libz.so.1`)を追加しました。
- hpkg は `/boot/system/apps/BDB/` に入ります。同梱データ(presets、samples、themes、icons)は実行ファイルの隣から読みます。

## VM での確認(2026-10-18)

RenkuOS の VM で、次の操作を確認しました。

- 起動、スタート画面、サンプルを開く、カードの移動、文字の入力と保存
- 編集モード: パレットからのドラッグで部品を置く、取り消し、インスペクタ、テーマの切り替え(Windows 95)
- 一覧表示と検索、プリセットからの新規スタック、仮カード(入力すると保存される)、スイッチの保存
- CSV ウィザード: 6 つの画面を通して取り込み、画像を HTTPS で取得(NDL の IIIF 画像 4 件)、サムネイルの表示
- PDF: カード 1 枚を保存し、ホストの `pdftoppm` で日本語・画像・枠を確認
- ログ(`~/config/settings/BDB/logs/`)に error がないこと

VM で見つけて直した不具合:

1. **サムネイルが透明になる**: オフスクリーンの BBitmap に `B_OP_ALPHA` で描くと、アルファ値が 0 のまま残っていた。その結果、画像が表示されず、透明ありと判定されて PNG で保存されていた。縮小をソフトウェアで行うように変えた(JPEG で約 18KB)。
2. **PDF の日本語が豆腐になる**: `BFont::GetGlyphShapes` はフォールバックフォントを使わない。主フォントにない文字は、app_server と同じ順序(Noto Sans → … → Noto Sans CJK JP …)のフォントから輪郭を取るようにした。
3. **ウィンドウを小さくできない**: レイアウトを持たない BView は、現在の大きさを最小サイズとして返す(`BView::MinSize` の既定)。カード面、一覧、アイコン一覧に最小サイズを明示した。編集モードの出入りでウィンドウが伸びる問題も、これで解消した。
4. **ウィンドウが広がる**: ステータスバーにリンクの URL を表示したときや、編集モードのバナーを表示したときに、ウィンドウが文字列の幅まで広がっていた。最小幅を指定して切り詰めるようにした(バナーはツールチップで全文を表示)。
5. **パレットとインスペクタの配置**: 重なったり、画面の下にはみ出したりしていた。スタックのウィンドウの横(右に空きがなければ左)に置き、インスペクタはパレットの下に画面に収まる高さで置くようにした。中身はスクロールできる。インスペクタの幅も中身に合わせた。
6. **CSV ウィザード**: 「自動(%s)」の `%s` が置き換わらない(メニューフィールドの表示が更新されない)、ウィンドウが狭くなる、既存テンプレートがないときにメニューに内部名(templates)が出る。
7. **スタート画面**: 最近使ったスタックの一覧が狭く、名前が切れる。
8. **新しいスタックのウィンドウ**: カードの下に余白が出る。実測した余白で、カードぴったりの大きさにした。
9. **向き**: 画面用の標準(512×342)で「縦」と表示される。用紙の指定がないときは、カードの縦横比で決めるようにした。
10. **ショートカット**: インスペクタにフォーカスがあると、Alt+B / L / F でモードを切り替えられない。

気づいたが、そのままにしている点:

- 部品が重なっているとき、プレイモードでは入力欄(実際のビュー)が上に描かれる。そのため、重なったボタンが入力欄の下に隠れる。
- 「連札」のサンプルの画像の取得は 30 件とも失敗する(`not_image`)。CSV の URL がビューアのページで、画像ではないため。入出力仕様 3.7 の注意どおり。

## VM での確認(2026-10-19、2 回目)

前回確認できなかった点を、VM で確認しました。

- 日本語入力: 1 行・複数行のテキスト枠で変換と確定(確定の Enter で次の欄へ移らない)、拡大表示中の候補ウィンドウの位置
- 拡大・縮小・等倍、数字枠(数値でない値は警告して元に戻す、`decimals` で丸めて表示)、ボタン(前へ・次へ、端で無効)、カウンター
- テーマ: Haiku(システムの色を変えると、すぐにカードの色も変わる)、NeXTSTEP、Mac OS
- リンク: 確認のダイアログ、WebPositive が開く、`mailto:` でメールが開く、`file:` はボタンが無効になり開かない、「このスタックでは、確認しない」
- PDF: 一覧の PDF(A4 縦で 2 ページ、見出しの行を繰り返す)、すべてのカード(A6 横で 30 ページ、進捗のダイアログ)
- CSV: `renfudasample.csv`(読み飛ばし 1 行)と、その Shift_JIS 版で 30 枚(画像は 30 件とも `not_image`)、取り込み中のキャンセル(新規スタックは何も残らない)
- 言語: ロケールを英語にすると、メニュー・スタート画面・プリセットが英語になる
- 用紙サイズのダイアログ(新規作成のとき、テンプレートのメニューから)、インスペクタの用紙サイズ

2 回目に見つけて直した不具合:

1. **用紙サイズのプルダウンでフリーズする**(真っさらなカードから始めるとき、テンプレートの「用紙サイズと向き」): 幅・高さの欄に数字を書くと、その欄の変更通知で表示の更新が呼ばれ、また数字を書く、という繰り返しでメッセージが溜まり続けていた。メニューの追跡がそのキューの検索に時間を取られ、操作を受け付けなくなっていた。数字が変わるときだけ書き、変更通知は「自由な大きさ」のときだけ受けるようにした。
2. **自由な大きさの向き**: 幅 600 × 高さ 794 でも「横」のまま保存された。自由な大きさでは、縦横の比から向きを決める(ダイアログの表示も合わせる)。
3. **用紙サイズのダイアログ**: 選んだ項目によって、メニューの幅が変わっていた。いちばん長い項目の幅にそろえた。
4. **最近使ったスタック(ファイルメニュー)**: 通常のスタックが、マニフェストのフルパスで表示されていた。スタート画面と同じく、スタックの名前で表示する。
5. **Haiku テーマ**: システムの色を変えても、開いているカードの色が変わらなかった(`B_COLORS_UPDATED` で描き直す)。
6. **CSV ウィザード(列の割り当て)**: 1 行に並べたオプションがウィンドウより広く、右端が切れていた。2 行に分け、ウィンドウの最小幅も中身に合わせた。
7. **CSV ウィザード(テンプレート)**: 新規スタックのとき、使わない対応表の枠(空のスクロール)が出ていた。

## 仕様ごとの対応

### データ形式 v0.4

- 部品 `bool` / `button` / `counter`、`background`、`paper`(7 種と custom、96 dpi 換算、`size` と食い違えば custom)、`theme`、`style`(border / fill / font、範囲外は不正)、`locked`、`icon`(button / label のみ)、`link`(image / label / button のみ)、`source`(image のみ)。未知の `action` は保持。
- 部品 ID の接頭辞 `f_` / `l_` / `b_` / `c_`。
- 仮カード: `CreateProvisionalCard` / `CommitIfChanged` / `DiscardProvisional`。初期値と違う値になった時点で rev 1 で保存し、`card.create` を記録。初期値に戻した場合は保存しない。
- 空のスタックはカード 0 枚、選んだ用紙の大きさ。
- 整理は `background.image` とアイコンも使用中として数え、`themes/` には触れません。
- 一括処理(整理、値の変換、seq の振り直し、CSV 取り込み)は、1 枚ごとの fsync を省き、最後に `sync()` します(12 章の【案】)。
- ログ: `theme.apply`、`sample.copy`、`link.open`、`link.blocked`、`stack.csv_import`、`image.fetch.failed`、`export.pdf`、`export.pdf.failed`、`stack.update` の `fields`、`app.start`/`app.quit` の `lang`。URL・値・タイトルは記録しません。

### UI v0.3

- モード名(プレイ・編集・検索)。編集モードは青いバナー(テンプレート名と使うカードの枚数、[編集を終える])、ウィンドウのタイトル、カード面の外側の色、グリッド、全部品の枠、名前と型の表示で区別。検索モードは黄色いバナー。
- メニューはモードごとに作り直します(編集モードは「部品」「テンプレート」があり「カード」「スタック」がない、など)。
- ウィンドウのナビゲーションボタンと番号欄を廃止。ステータスバーは「カード 12 / 300 ・ テンプレート: 名刺管理」。テンプレート名のクリックで編集モード。「カード番号へ移動…」(Alt+G)は小さな入力ウィンドウ。
- カードの中のボタン(動作の一覧はデータ形式仕様 7 章)と位置の表示。最初・最後のカードでの無効表示、押している間のへこみ、ポインターを重ねたときの明るさ、ツールチップ。
- オブジェクトパレット: 14 項目(枠、テキスト、数字、スイッチ、画像、ラベル、ボタン、最初へ・前へ・次へ・最後へ、ナビゲーションの組 2 種、位置の表示)。ドラッグして置く(置く場所の枠を表示、グリッドにスナップ)か、クリックしてからカード面をドラッグして大きさを決める。置いた後は「名前」(ボタンは「文字列」)にフォーカス。既定の名前は「テキスト1」「Text 1」。
- インスペクタ: 部品(名前、型、位置と大きさ、種類ごとの設定、アイコン、リンク、画像の取得元、スタイル、ロック)、複数選択(位置と大きさ、スタイル、ロック)、何も選択していないときはテンプレートのプロパティ(名前、用紙と向き、幅と高さ、タイトルに使う項目、背景色、背景画像とはめ方、テーマ、全テンプレートへの適用)。テーマの値は薄く表示。ロック中はロック以外を無効。色は色の選択ウィンドウ(最近使った色つき)。
- ロック: Alt+K / Shift+Alt+K、すべて、右クリック。鍵のマーク、ハンドルなし、禁止のカーソル。
- 前面へ・背面へ(Alt+] / Alt+[)、右クリックのメニュー(部品・空いた場所・プレイモード・一覧の行)、カーソル(移動、リサイズ、リンク、禁止)。
- 編集モードで画像ファイルを空いた場所にドロップ: 「背景にする」「画像枠として置く」(画像枠の初期値になります)。
- 仮カード: カード 0 枚のスタックを開くと新規カードの入力画面(1 / 1)。入力がなければ保存しない。
- 入力中に別のカードへ移動・モード切り替え・閉じる・終了するときは保存してから。保存に失敗したら移動しません。
- 新規作成で用紙サイズと向き(プレビュー、自由な大きさ)。最後の選択を次回の既定に。
- サンプル: 初回の起動で「最近使ったスタック」に「サンプル」の印つきで並びます。初めて開くときに `~/Documents/BDB/Samples/` にコピー(`sample.copy`)。右クリックで「一覧から外す」(入れ直すまで戻らない。アプリのファイルの更新時刻で判定)。ネットから画像を取るサンプルは初回に確認。
- UI の言語: システムの最優先言語が日本語なら日本語、それ以外は英語(取得できなければ日本語)。プリセットとサンプルも言語別。
- 一覧: 複数選択(Shift で範囲、Alt/Ctrl で追加)、「ファイル」の PDF 3 種、「すべて選択」、行の右クリック、スイッチの ✓。

### テーマ v0.1

- 同梱 5 種(`beos` 既定、`haiku`、`nextstep`、`macos`、`win95`)。`tools/make_themes.py` で生成し、`beos` はコアにも組み込み(ファイルがなくても既定が使える)。
- 見た目の種類 none / flat / raised / sunken / raised2 / sunken2 / etched / round。線は画面の拡大縮小でも整数ピクセルに合わせて描きます。
- `haiku`(native): 色をシステムの色(パネル、文書の背景と文字、枠、キーボードナビゲーションの色など)に置き換え、入力欄・ボタンの塗りもシステムに合わせます。`BControlLook` による描画までは使っていません(要確認事項)。
- テーマの適用でスタックの `themes/` にコピー。同じ rev ならコピーせず、違えば確認して上書き。利用者のテーマは `~/config/settings/BDB/themes/`。
- アイコン: haiku-icons(commit ccf434a)の HVIF 439 個を `icons/hvif/` に同梱。Haiku の商標・ロゴのもの(App_Haiku3d、HaikuDepot_*、Folder_haiku、Misc_HaikuBook、Overlay_leaf)は除外。MIT の表示と出典は「このアプリについて」と `icons/LICENSE`、`icons/README`。選んだアイコンはスタックの `media/image/` に新しい media_id でコピーし、同じ内容があれば再利用。

### 入出力 v0.1

- リンク: 固定の URL と項目から。http / https / mailto 以外、2048 文字超、空白・制御文字、ホストなしは開きません(ステータスバーに理由、`link.blocked`)。スタックごとに最初は確認(「このスタックでは、確認しない」は設定に保存)。`BUrl::OpenWithPreferredApplication` で既定のブラウザ。手のカーソルとツールチップで URL を表示。プレイモードだけで動作。
- CSV 取り込み: ウィザード 8 画面(ファイル → 形式 → 列 → テンプレート → 画像 → 確認 → 取り込み中 → 完了)。文字コード・区切りの自動判定と変更、見出し行、プレビュー。上限(512 MiB、100 万行、1 値 1 MiB)は確認画面の前の走査で判定し、超えるときは始めません。新規スタックは一時フォルダに作り、キャンセル・失敗で丸ごと破棄。既存スタックへの追加は、キャンセルしても作成済みのカードを残します。
- 画像の取得: タイムアウト 15 秒、リダイレクト 5 回、20 MiB、同時 4(同じホストは 2)、再試行 1 回、User-Agent `BDB/0.2.0`。`Content-Type: image/*` とデコードで判定(違えば `not_image`)。サムネイルは長辺 128/256/512、拡大しない、EXIF の向きを反映(JPEG トランスレータが補正)、JPEG 品質 85(透明があれば PNG)。500 行以下は取り込みと同時、それより多い(または推定用に読んだ 1000 行で終わらない)ときは既定でバックグラウンド。「スタック」→「画像を取得…」で未取得だけ再取得。
- PDF: 現在のカード、選択したカード、すべてのカード(1 枚 1 ページ、テンプレートの用紙、なければ 96 dpi 換算)、一覧(用紙と向きを選択、既定 A4 横、見出しの繰り返し、最大 3 行で「…」、フッターにスタック名・テンプレート名・ページ番号)。ボタンと位置の表示は出しません。「背景を印刷する」。20 ページ以上で進捗とキャンセル。書きかけは残しません。

## PDF の実装方法(入出力仕様 4.6)

コアに自前の PDF 書き出しを持ち、文字は **Type 3 フォント**で埋め込みます。各文字の輪郭はアプリが `BFont::GetGlyphShapes` でシステムのフォントエンジンから受け取り、ベクターのまま PDF に入れます。ToUnicode も付けるので、検索とコピーができます。

この方法を選んだ理由: RenkuOS の日本語フォントは `NotoSansCJKjp-VF.otf`(CFF2 の可変フォント)で、PDF はこの形式をそのまま埋め込めません。`BPrintJob` と PDF 書き出しドライバーは RenkuOS に入っているか不明で、cairo は依存が大きいため、どのフォントでも動き、32bit/64bit で同じコードになるこの方法にしました。枠線などはベクター、JPEG ファイルは再圧縮せずそのまま、その他の画像は可逆(Flate)で埋め込みます。

## 仕様に対して判断・追加したこと

1. **bool の `style` の衝突**: データ形式仕様 7 章で、`bool` の `style` は文字列(`switch` / `checkbox`)、共通の `style` はオブジェクト(枠線など)と、同じキーが二通りに定義されています。試作では、見た目の設定がないときは文字列のまま書き、見た目の設定があるときはオブジェクトにして `"control": "switch"` を中に入れました(読み込みは両方を受け付けます)。仕様側で決めてください。
2. **`renfudasample.csv` が仕様の説明と違う**: 実際のファイルは、1 行目に `renfudasample` という表題の行があり、改行が CRLF、URL は `https://dl.ndl.go.jp/pid/...` です(仕様は「LF、見出しの行あり、URL は https://ndl.go.jp」)。このため、ウィザードの形式の画面に「先頭から読み飛ばす行」を追加しました(仕様にない項目)。同梱の「連札」は、1 行読み飛ばして作っています(30 枚)。URL はビューアのページなので、仕様の想定どおり画像の取得は `not_image` で失敗するはずです。
3. **文字コードの変換**: `iconv` を使わず、CP932 と EUC-JP(JIS X 0208、半角カナ)の変換表をコアに持ちました(Python の codecs から生成、`tools/make_jis_tables.py`)。RenkuOS の開発用ヘッダに `iconv.h` がなく、コアを POSIX のみに保つためです。JIS X 0212(補助漢字)は U+FFFD になります。
4. **使い方の推定**: 値が 0/1 だけの列は、数字ではなくスイッチにしました(仕様は数字を先に書いていますが、0/1 はスイッチの例にも挙がっているため)。
5. **画像(URL)で「URL を項目として残す」をオフにした列**: 取得元を記録できないので、取り込みと同時に取得します(後から再取得はできません)。
6. **リンク先にする対象**: CSV の「リンク(URL)」列は、画像(最初のリンク列、既定)とボタンのリンク先にできます。ラベルを対象にする選択はまだありません。
7. **自動レイアウト**: タイトルの項目は 4 ポイント大きい文字。用紙が決まっていて収まらないときは 2 列、それでも収まらないときは高さを増やして用紙を custom にします。
8. **フォントの大きさの単位**: `size` は、カード面の論理ピクセル(96 dpi)での大きさとして扱いました(画面と PDF で同じ見た目になります)。仕様の「ポイント」との差は要確認です。
9. **一覧の PDF の進捗**: 一覧はページ数を先に数えないため、400 行以上で進捗を出します。
10. **一括処理の fsync**: 最後に `sync()`(ボリューム全体)を呼びます。
11. **整理のメッセージ(英語)**: 英語の文の語順に合わせて引数の順を入れ替えています。
12. **CSV 取り込み中のスタック**: 既存スタックへの取り込みは、25 枚ごとにロックを手放して他のウィンドウを描画させます。「URL を残さない」画像列の取得中は、その間カード面の操作が待たされることがあります。
13. **robots.txt**: 「取得を禁止するサイトからは取得しない」は、注意の表示だけで、robots.txt などの自動判定はしていません。

## v0.5 の変更(2026-10-19)

### 名前と拡張子

- アプリの名前: 連札(英語表示では Renfuda)。実行ファイルは `Renfuda/Renfuda`、配布物は `Renfuda.zip` と `renfuda-0.5.0-1-x86_64.hpkg`。

- **注意**: v0.4 以前で作ったスタック(`.bdbf`)は、そのままでは開けない。フォルダと中のファイルの拡張子を `.rfd*` に付け替えると開ける。以前の設定(最近使ったスタックなど)も引き継がない。
- ソースの内部名(`bdb::` 名前空間、`BDB_` で始まるマクロ)は変えていない。

### ボタンの動作(試作の拡張)

インスペクタの「動作」に次の 4 つを追加した。

| 動作 | 値 | 内容 |
| --- | --- | --- |
| カードをPDFで保存 | `card.pdf` | 「現在のカードをPDFで保存」と同じ |
| カードを画像で保存 | `card.image` | 今のカードを、プレイモードの見た目(値つき、スイッチで隠した部品は除く)で、等倍の PNG に保存する |
| 音を鳴らす | `sound.play` | ボタンに設定した音のファイルを再生する(BFileGameSound)。再生中にもう一度押すと止まる |
| 動画を再生する | `video.play` | ボタンに設定した動画のファイルを、その種類の既定のアプリ(MediaPlayer)で開く。プレーヤーのウィンドウ名は元のファイル名 |

- 音・動画のファイルは、インスペクタの「音・動画」→「選ぶ…」で設定する。スタックの `media/audio/`・`media/video/` にコピーされ、ボタンの `"media"` に参照を持つ(データ形式のメディア参照と同じ形)。音のボタンには音の、動画のボタンには動画のファイルだけを設定できる。
- ファイルが設定されていないとき、音・動画のボタンは押せない(薄く表示)。
- 元のファイル名は、メディア参照の `"name"` に記録する(インスペクタにも表示)。スタック内のファイルは ID の名前なので、動画を開くときは、一時フォルダ(`/boot/system/cache/tmp/Renfuda-video-<uid>/`)に元の名前でコピーしてから開く(MediaPlayer はシンボリックリンクをたどってリンク先の名前を表示するため)。コピーは別スレッドで行い、同じ大きさ・日時のコピーがあれば使い回す。次に連札を起動したときに消す。v0.5 の最初の版で設定した動画は名前を持たないので、設定し直すと元の名前になる。

### スイッチの動作(試作の拡張)

スイッチに、オンのあいだの動作を持たせた。インスペクタの「スイッチの動作(オンのとき)」で選ぶ。

- **このカードの編集をロック**: そのカードのすべての部品を読み取り専用にする(テキストに入力できない、ほかのスイッチを切り替えられない、画像を設定できない)。ロックした入力欄は、クリックしても選択されず、カーソルも出ない(Tab キーでも移らない)。ロックしたスイッチ自身は操作でき、オフにすると解除される。
- **指定した部品をロック**: チェックした部品(複数可)を読み取り専用にする。入力欄の扱いは上と同じ(選択されない)。ロックした画像の枠には、ドロップでも画像を設定できない。
- **指定した部品を隠す**: チェックした部品(複数可)を表示しない。PDF とカードの画像にも出ない。
- テンプレートの部品に `"effect": { "type": "lock_card" | "lock" | "hide", "targets": [部品ID…] }` として保存する。スイッチの値はカードごとなので、カードごとにロックや表示を切り替えられる。スイッチ自身を対象にはできない。
- 検索モード・編集モードでは効かない(すべての部品を表示・操作できる)。

### 画像の枠

- 画像の入った枠をダブルクリックすると、画像を本来の大きさで別のウィンドウに表示する(画面より大きいときはスクロール。Esc で閉じる)。空の枠のダブルクリックは、従来どおり画像ファイルを選ぶ。
- 画像の枠にリンク(http・https の URL、またはテキスト部品の値)を設定したときは、クリックでリンク先を開く(確認のダイアログは従来どおり)。

### 設定(ファイル → 設定…、Alt+,)

- リンクを開くブラウザを選べる: 「システムの既定のブラウザ」または「次のアプリケーション」(パスを入力するか「選ぶ…」で指定)。http と https のリンクに使い、`mailto:` などはシステムの既定のアプリで開く。設定したブラウザが見つからないときは、既定のブラウザで開き、ステータスバーで知らせる。

### アプリのアイコン

- 3 枚の縦長の札(青・朱・生成り)が扇形に重なった、BeOS 風のアイコン(左上からの光、濃い輪郭、右下の影)。手前の札に墨で「札」、下に朱の印。
- `tools/make_icon.py` が、ベクターアイコン(HVIF)を作って `app/BDB.rdef` の `vector_icon` に書き込み、`app/Renfuda.hvif` も出力する。引数に PNG のパスを渡すと、プレビュー(大きい絵と 32 ピクセル)を書き出す。
- hpkg: 実行ファイルに `BEOS:ICON`・`BEOS:APP_SIG`・`BEOS:TYPE` の属性を付けて梱包する(ホスト用の `addattr`)。
- zip: Linux で作るので属性がない。連札が起動時に、自分の実行ファイルにアイコンの属性がなければ、mimeset と同じ処理(`update_mime_info`)でリソースから属性を作る。Tracker にもアイコンが出る。

### スタックとファイルのアイコン

- `tools/make_icon.py` が、アプリのアイコンのほかに次の 4 つを作る(`app/BDB.rdef` に書き込む)。
  - スタック: 黄色いフォルダ(箱)に 3 枚の札が立っている。スタックのフォルダ(`.rfdf`)とマニフェスト(`.rfdm`)に使う
  - カード(`.rfdd`): 「札」と朱印の札 1 枚
  - テンプレート(`.rfdt`): 空の枠が並んだ青い札
  - テーマ(`.rfds`): 色見本の並んだ札
- ファイルのアイコン: 起動時に、MIME タイプ(`application/x-vnd.renfuda-*`)にアイコンを登録する。リソース名は `BEOS:L:<タイプ>`(アプリが扱う種類のアイコン)。
- スタックのフォルダ: スタックを開くとき(作った直後を含む)に、フォルダに `BEOS:ICON` 属性でスタックのアイコンを付ける。起動時にも、最近使ったスタックとコピーしたサンプルに付ける。独自のアイコンが付いているフォルダや、書き込めないフォルダはそのまま。
- スタックを開くとき、中のファイルに拡張子から種類(`BEOS:TYPE`)を付ける(`update_mime_info`、バックグラウンド)。Tracker でマニフェストやカードのアイコンが出るようになる。新しく作ったカードは、次に開いたときに種類が付く。
