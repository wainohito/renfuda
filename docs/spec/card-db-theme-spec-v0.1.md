# BDB カード型DB テーマ仕様 v0.1(テーマ、アイコン、BeOSらしさ)

状態: ドラフト
対象: カード面の見た目(部品の枠、背景、ボタン、文字)と、アイコン
読者: 試作の実装者
前提: `card-db-spec-v0.4.md`(データ形式)、`card-db-ui-spec-v0.3.md`(UI)

表記:

- 「必須」は必ず守る。「推奨」は理由がなければ守る。「任意」は実装者の判断。
- **【案】** は、まだ確定していない提案。色の値は、実機で見て調整してよい。

## 1. 目的と範囲

- カード面の見た目を、テーマのファイルで切り替えられるようにする。
- BeOSらしい見た目と挙動を、既定にする。MacやNeXTやWindows風のテーマも選べる。
- ボタンや見出しに、BeOS風のアイコンを使えるようにする。
- **対象**: カード面の中(部品の枠、背景、ボタン、入力欄、文字)。
- **対象外**: ウィンドウの枠とタイトル、メニュー、パレット、インスペクタ、ダイアログ。これらは、システムのものを使う。

## 2. 用語

| 用語 | 意味 |
|---|---|
| テーマ | カード面の見た目を決める、1つのファイル(`.bdbs`) |
| 見た目の種類(`look`) | 枠や部品の立体の付け方。第4章の一覧 |
| 部品のスタイル | 部品ごとの設定(`style`)。テーマの値より優先される |

## 3. テーマの置き場所と選び方

### 3.1 置き場所

| 場所 | 内容 | 書き込み |
|---|---|---|
| アプリに同梱 | 同梱のテーマ(第6章) | 読み取り専用 |
| 利用者のテーマ | `~/config/settings/BDB/themes/` | 利用者がファイルを置く |
| スタックの中 | スタックの `themes/` | アプリが、テーマを適用するときにコピーする |

### 3.2 参照と探す順

- テンプレートの `theme` に、テーマのID(`theme_id`)を書く。
- 探す順は、スタックの中、利用者のテーマ、同梱のテーマ。最初に見つかったものを使う。
- 見つからないときは、既定のテーマ(`beos`)を使い、問題リストに記録する(理由は `theme_missing`)。

### 3.3 テーマの適用

- 利用者がテンプレートにテーマを適用したとき、そのテーマのファイルを、スタックの `themes/` にコピーする。同じ `theme_id` で、同じ `rev` のファイルがすでにあれば、コピーしない。`rev` が違うときは、利用者に確認して上書きする。
- コピーする理由: スタックをZIPなどで配布しても、受け取った人の環境で、同じ見た目になるようにするため。
- 整理は、`themes/` のファイルを削除しない。

### 3.4 テーマのIDと名前

- `theme_id`: `^[a-z][a-z0-9_-]{0,31}$`。人が読める名前にする(ランダムにはしない)。同梱のテーマは、`beos`、`haiku`、`nextstep`、`macos`、`win95`。
- 利用者が作るテーマのIDは、同梱のIDと重ならないようにする。重なったときは、探す順(第3.2章)のとおり、スタックの中のものが優先される。

## 4. テーマのファイル(`.bdbs`)

JSON(UTF-8)。最初の2つのキーは `bdb`(値は `theme`)と `format_version`(1)。未知のキーは無視する。

### 4.1 例(BeOS風)【案】

```json
{
  "bdb": "theme",
  "format_version": 1,
  "theme_id": "beos",
  "rev": 1,
  "name": { "ja": "BeOS", "en": "BeOS" },
  "description": { "ja": "BeOS R5 風の、立体的な見た目", "en": "A beveled look in the style of BeOS R5" },
  "native": false,
  "colors": {
    "panel": "#d8d8d8",
    "text": "#000000",
    "text_disabled": "#808080",
    "control_fill": "#ffffff",
    "control_border": "#808080",
    "accent": "#ffcb00",
    "link": "#0000ee",
    "bevel_light": "#ffffff",
    "bevel_dark": "#909090",
    "bevel_darker": "#606060"
  },
  "font": { "family": "", "style": "Regular", "size": 12 },
  "kinds": {
    "text":    { "look": "sunken", "border": { "visible": true, "width": 2 }, "fill": "#ffffff" },
    "number":  { "look": "sunken", "border": { "visible": true, "width": 2 }, "fill": "#ffffff" },
    "bool":    { "look": "raised", "border": { "visible": true, "width": 2 } },
    "image":   { "look": "sunken", "border": { "visible": true, "width": 2 } },
    "label":   { "look": "none" },
    "button":  { "look": "raised", "pressed": "sunken", "border": { "visible": true, "width": 2 }, "fill": "#d8d8d8" },
    "counter": { "look": "sunken", "border": { "visible": true, "width": 1 }, "fill": "#e8e8e8" },
    "blank":   { "look": "flat", "border": { "visible": true, "width": 1 } }
  },
  "focus": { "color": "#ffcb00", "width": 2 }
}
```

### 4.2 キー

| キー | 内容 |
|---|---|
| `theme_id` | テーマのID(第3.4章) |
| `rev` | 整数。テーマを変えるたびに増やす。1から始める |
| `name`、`description` | 表示する名前と説明。`ja` と `en`。UIの言語に合わせて表示する。どちらかがなければ、もう一方を使う |
| `native` | 真偽値。`true` のときは、Haikuのシステムの描画(`BControlLook` とシステムの色)を使い、`colors`、`kinds` のうち、システムが決める項目は無視する。既定は `false` |
| `colors` | 色の一覧(下記)。`#rrggbb` |
| `font` | 既定のフォント。`family` が空のときは、システムの標準のフォント。`size` は 6〜96 |
| `kinds` | 部品の種類ごとの既定(`text`、`number`、`bool`、`image`、`label`、`button`、`counter`、`blank`)。省略した種類は、`flat` の細い枠で描く |
| `focus` | キーボードのフォーカスと選択の枠の色と太さ |

`colors` のキー:

| キー | 用途 |
|---|---|
| `panel` | カード面の背景(テンプレートの `background.color` がないとき) |
| `text`、`text_disabled` | 文字の色、無効のときの文字の色 |
| `control_fill` | 入力欄などの中の色 |
| `control_border` | `flat` の枠線の色 |
| `accent` | 選択、フォーカス、強調の色 |
| `link` | リンクの文字の色 |
| `bevel_light`、`bevel_dark`、`bevel_darker` | 立体の枠の、明るい線、暗い線、さらに暗い線(外側の線など) |

`kinds` の各項目のキー(すべて任意):

| キー | 内容 |
|---|---|
| `look` | 見た目の種類(第4.3章) |
| `border` | `{ "visible": true, "width": 2, "color": "#rrggbb" }`。部品の `style.border` で上書きされる |
| `fill` | 枠の中の背景色。`null` は透明。部品の `style.fill` で上書きされる |
| `font` | その種類の文字のフォント。部品の `style.font` で上書きされる |
| `radius` | 角の丸み(ピクセル)。`round` のときに使う |
| `pressed` | `button` を押している間の見た目の種類(例: `sunken`) |

### 4.3 見た目の種類(`look`)

| `look` | 見た目 |
|---|---|
| `none` | 枠なし(`border.visible` が偽と同じ) |
| `flat` | 1色の線。太さと色は `border` |
| `raised` | 浮き出した立体。左と上が `bevel_light`、右と下が `bevel_dark` |
| `sunken` | へこんだ立体。`raised` の逆 |
| `raised2` | 二重の立体(浮き出し)。外側に `bevel_darker` の線を加える。NeXTSTEPやWindows 95風 |
| `sunken2` | 二重の立体(へこみ) |
| `etched` | 溝(明るい線と暗い線の2本) |
| `round` | 角丸の線。`radius` で丸みを決める。Mac OS風 |

- 未知の `look` は、`flat` として扱う。
- `border.width` が 0、または `border.visible` が偽のときは、枠線を描かない(立体の線も描かない)。
- ボタンの状態: 通常、ポインターを重ねたとき(わずかに明るくする)、押している間(`pressed`)、無効(文字を `text_disabled`)、フォーカス(`focus`)。

## 5. 見た目を決める順序

1つの項目(例: テキスト枠の枠線の太さ)は、次の順で決める。最初に見つかった値を使う。

1. 部品の `style`
2. テーマの `kinds` のその種類
3. テーマの `colors`、`font`
4. 既定のテーマ(`beos`)

- 部品の `style` に書いていない項目は、テーマの値になる。テーマを変えると、書いていない項目だけが変わる。
- テーマに `native: true` を指定した場合は、描画をシステムに任せる。ただし、部品の `style` は、そのまま優先する。

## 6. 同梱のテーマ【案】

配色、線、形の組み合わせだけを再現する。OSの画像資産、ロゴ、フォントは、同梱しない。フォントは、`family` に名前を書き、ないときはシステムの標準のフォントにする。色は、実機で見て調整する。

| `theme_id` | 名前 | 特徴 |
|---|---|---|
| `beos` | BeOS | 既定。薄いグレーの面、立体のボタン(押すとへこむ)、へこんだ入力欄、黄色のアクセント |
| `haiku` | Haiku | `native: true`。システムの色と描画に従う。システムの設定を変えると、見た目も変わる |
| `nextstep` | NeXTSTEP | 濃いグレー系の面、黒の外枠のある二重の立体(`raised2`、`sunken2`)、白い入力欄 |
| `macos` | Mac OS | 明るいグレーの面、角丸のボタン(`round`)、細い黒の枠、青紫系のアクセント。Mac OS 8〜9のPlatinum風 |
| `win95` | Windows 95 | `#c0c0c0` の面、二重の立体(`raised2`、`sunken2`)、紺色のアクセント(`#000080`) |

| 項目 | `beos` | `nextstep` | `macos` | `win95` |
|---|---|---|---|---|
| `panel` | `#d8d8d8` | `#aaaaaa` | `#dddddd` | `#c0c0c0` |
| `bevel_light` | `#ffffff` | `#ffffff` | `#ffffff` | `#ffffff` |
| `bevel_dark` | `#909090` | `#555555` | `#888888` | `#808080` |
| `bevel_darker` | `#606060` | `#000000` | `#000000` | `#000000` |
| `accent` | `#ffcb00` | `#333333` | `#99aadd` | `#000080` |
| 入力欄の `look` | `sunken` | `sunken2` | `sunken` | `sunken2` |
| ボタンの `look` | `raised` | `raised2` | `round` | `raised2` |
| フォント(参考) | システム標準 | Helvetica系 | Charcoal、Geneva系 | MS Sans Serif系 |

- 「Mac」と「Windows」は、どの時代の見た目にするかを、確認したい(第9章)。上の表は、クラシックな時代(Mac OS 8〜9、Windows 95)を想定している。

## 7. BeOSらしい見た目と挙動(要件)

「BeOSネイティブのアプリらしい、パーツのデザインと挙動」を実感できるようにするための要件。既定のテーマは `beos`。

### 7.1 見た目

- **必須**: カード面の部品は、`beos` テーマで、立体的なボタン(押すと、へこむ)、へこんだ入力欄、薄いグレーの面、黄色のアクセントで描く。
- **必須**: 文字は、システムの標準のフォントを使う(テーマとスタイルで変えられる)。
- **推奨**: 枠線や立体の線は、画面の拡大縮小でも、くっきり描く(1ピクセルの線を、ぼかさない)。
- **推奨**: パレット、一覧、ダイアログのアイコンに、HaikuのHVIFアイコンを使う(第8章)。

### 7.2 挙動

| 挙動 | 要件 |
|---|---|
| ドラッグ&ドロップ | **必須**: パレットから部品を置く、画像ファイルを画像枠に落とす、テキストを枠の間でドラッグしてコピー・移動する。**推奨**: カードのファイルを、一覧からTrackerへドラッグできる |
| 右クリックのメニュー | **必須**: カード面、部品(編集モード)、一覧の行で、右クリックのメニューを出す |
| ツールチップ | **推奨**: ボタン(動作の名前)、リンク(URL)、アイコンのボタンで、ツールチップ(`BToolTip`)を出す |
| ライブ更新 | **必須**: 同じスタックの別のウィンドウ(カード面と一覧)に、変更がすぐ反映される。**推奨**: 外部でファイルが変わったとき(`BNodeMonitor`)に、一覧に反映する |
| キーボード | **必須**: Altキーのショートカット、Tabキーでの入力欄の移動、Enter・Escの標準の動作 |
| 反応の速さ | **必須**: スクロールやリサイズの最中も描画が止まらない。時間のかかる処理(CSV取り込み、PDF出力、画像の取得)は、別のスレッドで行い、画面を固めない |
| システムへの追従 | **推奨**: `haiku` テーマでは、システムの色とフォントの設定に従う |
| ライブクエリ | **後続**(Phase 3): 一覧が、BFSのライブクエリで、自動的に更新される |
| Replicant | **後続**: カードの部品を、デスクトップに置けるようにする(`BDragger`) |

## 8. アイコン

### 8.1 素材

- 素材: haiku-icons(`https://github.com/darealshinji/haiku-icons`)。Haikuのアイコンを、HVIF、SVG、PNGの形式で書き出したもの。元は、Haikuの `data/artwork`。
- 使う形式は、**HVIF**(ベクターで、小さく、どの大きさでも綺麗に描ける)。リポジトリの説明に、「SVGとPNGは、正しく書き出されていないものがある」とあるので、SVGとPNGは使わない。
- ライセンス: 基本はMIT。ただし、Haikuの商標のもの(ロゴ、葉のマーク、背景の葉のマーク)は、**同梱しない**。アプリの「このアプリについて」に、MITライセンスの表示と、出典を載せる。

### 8.2 同梱と探し方

- 同梱する場所: アプリの `icons/hvif/`。ファイル名が、アイコンの名前(英語)になる。
- 描画は、`BIconUtils`(Haikuのベクターアイコンの描画)で行う。大きさを変えても、綺麗に描ける。
- 用途: `button` と `label` のアイコン、パレットやメニューのアイコン(推奨)。

### 8.3 スタックへのコピー

- 利用者がアイコンを選んだとき、そのHVIFファイルを、スタックの `media/image/` に、新しい `media_id` でコピーする(`ext` は `hvif`)。部品の `icon` は、そのメディアを参照する。
- 同じ内容のファイルが、すでにスタックの `media/image/` にあれば、新しくコピーせず、それを参照する(内容のハッシュで判定)。
- こうする理由: スタックを配布しても、受け取った人の環境で、同じアイコンが表示されるようにするため(アプリのバージョンによって、同梱のアイコンが変わっても、影響されない)。

### 8.4 アイコン選択ダイアログ

- 開く場所: インスペクタの「アイコン」の欄の [選ぶ…]。
- 構成: 検索ボックス(名前の部分一致)、アイコンの一覧(格子状。名前を下に表示)、プレビュー(大きさを変えて表示)、[選ぶ] [キャンセル]。
- 大きさ(12〜128)と、文字列との位置(左、上)も、ここで選ぶ。
- 「ファイルから…」で、利用者が持っているHVIFや画像のファイルを選べる【案】。この場合も、スタックにコピーする。
