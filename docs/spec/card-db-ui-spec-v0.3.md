## 1. 方針

- **使いやすさと作りやすさを両立する**: 真っさらな状態から始めても、すぐに枠を置いて使い始められること。テンプレートから始めれば、設計せずに使い始められること。
- **FileMaker方式**: 「閲覧」「編集」「検索」の3つのモードを持つ。編集では、先に枠を配置し、型は後から設定する。
- **Haikuの作法に従う**: 標準のコントロール、メニューバー、ショートカット、ドラッグ&ドロップ、標準のダイアログ(`BFilePanel`、`BAlert`)、フローティングウィンドウ(パレット)を使う。
- **データを失わせない**: 型の変更や項目の削除でも値は消えない(データ形式仕様の孤立値)。取り返しのつかない操作は、必ず確認する。
- **保存を意識させない**: 編集は自動で保存する(第11章)。
- **UIの言語**: 既定は日本語。システムの言語が日本語でないときは、英語で表示する(第14.1章)。文言は1か所に集約する。
- **BeOSらしさ**: カード面の見た目と挙動は、テーマ仕様の第7章に従う。既定のテーマは `beos`。見た目は、テーマ(ファイル)で変えられる。
- **モードの区別**: プレイモードと編集モードは、見た目とメニューではっきり区別する(第4.1章)。

## 2. 画面とウィンドウ

### 2.1 スタックウィンドウ(カード面)

- 構成: メニューバー、カード面、ステータスバー。
- **カード面**: テンプレートの `size` の大きさの描画領域。部品を `rect` の位置に配置する。
  - 拡大率は、既定で等倍。ウィンドウがカード面より小さいときは、スクロールする。
  - 「ウィンドウに合わせる」を選べる(拡大縮小。第10章の「表示」メニュー)。
- **ステータスバー**: カードの位置(例: `12 / 300`)、現在のテンプレートの名前、現在のモード、検索中なら検索結果の件数(例: `検索結果 12 / 300`)。
- **ナビゲーション**: ウィンドウには、ナビゲーション用のボタンも番号の入力欄も置かない。カードの移動は、カードの中に置いたボタンと位置の表示(第6.10章)、メニュー、ショートカットで行う。ステータスバーの位置の表示(例: `12 / 300`)は残す。
- ウィンドウのタイトルは、モードによって変える(第4.1章)。

### 2.2 一覧ウィンドウ

- 表形式でカードを一覧するウィンドウ(第7章)。
- 1つのスタックに対して、スタックウィンドウと一覧ウィンドウを同時に開ける。どちらかでカードを変更すると、もう一方に反映する。

### 2.3 パレットとインスペクタ(編集モードのみ)

- フローティングウィンドウ(`B_FLOATING_WINDOW`)として表示する。
- **オブジェクトパレット**: 選択ツールと、置ける部品の一覧(第6.2章)。
- **インスペクタ**: 選択中の部品のプロパティを編集する(第6.4章)。

### 2.4 ウィンドウの基本動作

- 同じスタックを開こうとしたときは、すでに開いているウィンドウを前面に出す。
- ウィンドウの位置、大きさ、拡大率は、スタックごとに記憶する(アプリの設定として保存。スタックのフォルダには入れない)【案】。

## 3. 起動と新規スタック

### 3.1 起動時の動作

| 起動のしかた | 動作 |
|---|---|
| `.bdbm` をダブルクリック、またはアプリにドロップ | そのスタックを開く(スタートウィンドウは出さない) |
| `.bdbt` をアプリにドロップ | そのテンプレートを使って新規スタックを作る(第3.3章の「保存先の指定」から) |
| 引数なし | スタートウィンドウを出す |

### 3.2 スタートウィンドウ

次の5つを選べる。

1. **真っさらなカードから始める**
2. **テンプレートから始める**
3. **CSVから始める…**(第3.6章)
4. **スタックを開く…**(`BFilePanel`)
5. **最近使ったスタック**(一覧。最大10件【案】)。初回の起動では、同梱のサンプルスタックを、使ったことのあるスタックとして、最初から並べる(第3.5章)

### 3.3 新規スタックの作り方

**真っさらなカードから始める**

1. 用紙サイズと向きを選ぶ(第3.4章)。
2. 保存先と名前を指定する(`BFilePanel`。フォルダ名に `.bdbf` を付ける)。
3. 空のスタック(データ形式仕様の第19.1章)を作る。
4. 編集モードで開く。部品が1つもないので、そのまま枠を置き始められる。

**テンプレートから始める**

1. プリセットの一覧を表示する。カード面の縮小プレビューと、名前、短い説明を並べる。
2. 1つ選ぶ。
3. 保存先と名前を指定する。
4. プリセットをコピーして、スタックを作る(データ形式仕様の第19.2章)。
5. プレイモードで開く。カードが0枚なので、仮の新規カードの入力画面を開く(第5.5章)。

保存先の既定は、ユーザーのドキュメントのフォルダ【案】。

### 3.4 用紙サイズと向き

- 「真っさらなカードから始める」では、保存先の指定の前に、用紙サイズと向きを選ぶ画面を出す。
- 選べる用紙サイズ: 「画面用の標準(512×342)」(既定)、A4、A5、A6、B4、B5、B6、ハガキ、自由な大きさ(幅と高さを数字で入力)。寸法と換算は、データ形式仕様の第7章。
- 向き: 縦、横。選んだ用紙の形のプレビューを、画面に表示する。
- 選んだ値は、テンプレートの `paper` と `size` になる(あとで、テンプレートのプロパティから変えられる。第6.15章)。最後に選んだ値を、次回の既定にする【案】。
- 「テンプレートから始める」では、プリセットの大きさのままにする。変更は、テンプレートのプロパティで行う。
- 用紙が大きく、画面に収まらないときは、カード面を等倍でスクロールするか、「ウィンドウに合わせる」で縮小して表示する(第2.1章)。

### 3.5 サンプルスタック

- アプリに、サンプルのスタックを同梱する(プリセットを使ったもの、CSVから作ったものなど)。
- 初回の起動では、サンプルを、スタートウィンドウの「最近使ったスタック」の一覧に、最初から並べる。「サンプル」の印を付ける。
- 同梱のサンプルは、読み取り専用の場所にある。サンプルを初めて開くときに、`~/Documents/BDB/Samples/` にコピーしてから、そのコピーを開く【案】。2回目からは、コピーを開く。コピーを削除したときは、次に開くときに、もう一度コピーする(ログに `sample.copy` を記録する)。
- サンプルは、利用者が使ったスタックと同じ扱いにする(一覧の並びは、最後に開いた順)。一覧の項目を右クリックして、「一覧から外す」を選べる。外したサンプルは、アプリを入れ直すまで、一覧に戻らない。
- 画像をネットから取得するサンプル(「連札」など)は、初めて開くときに、「画像をネットから取得しますか?」と確認する。[取得する] [あとで]。取得は、バックグラウンドで行い、ステータスバーに進捗を出す。「あとで」を選んだときは、メニュー「スタック」→「画像を取得…」から取得できる(入出力仕様の第3.8章)。

### 3.6 CSVから始める

- スタートウィンドウの「CSVから始める…」、またはメニュー「ファイル」→「CSVから新規スタックを作る…」で、取り込みウィザードを開く。
- ウィザードの画面遷移と、取り込みの規則は、入出力仕様の第3章。
- 取り込み先は、新規のスタック。既存のスタックに追加するときは、メニュー「スタック」→「CSVを読み込む…」。

## 4. モード

| モード | できること | 切り替え【案】 |
|---|---|---|
| プレイモード(旧称: 閲覧) | カードの値の入力、カードの移動・追加・複製・削除 | Alt+B |
| 編集モード(テンプレートを編集する) | テンプレートの部品の配置、型の設定、削除、背景の設定 | Alt+L |
| 検索モード | 条件を入力して、カードを絞り込む | Alt+F |

- 起動直後と、スタックを開いた直後は、プレイモード(新規に作った空のスタックは、編集モード)。
- モードは、メニューの「モード」から切り替える。
- 編集モードから他のモードへ移るときに、テンプレートを保存する(第6.7章)。

### 4.1 いまのモードと、編集している対象を分かりやすくする(必須)

画面に表示するモードの名前は、「プレイモード」「編集モード」「検索モード」にする。「プレイモード」は、カードの内容を見る・入力するモード(旧称は「プレイモード」)。「編集モード」は、テンプレートを編集するモード。

**プレイモードと編集モードは、画面の見た目と、メニューの項目の両方で、はっきり区別する(必須)**。

「いま、カードの内容を入力しているのか、テンプレートを編集しているのか」が、ひと目で分かるようにする。

**編集モード(テンプレートの編集)**

- カード面の上に、目立つ色の帯(バナー)を、常に表示する。例:「テンプレートを編集中: 名刺管理 — このテンプレートを使う 300 枚のカードに反映されます」。右端に、[編集を終える] ボタンを置く。
- カード面には、グリッド(薄い点)と、すべての部品の枠線を表示する。カードの値は表示せず、各部品の名前と型を表示する。値が入っていないことで、カードの入力ではないと分かるようにする。
- ウィンドウのタイトルは、`<スタック名> — 編集モード: <テンプレート名>`。
- ウィンドウの背景(カード面の外側)の色を、プレイモードと変える(必須)。色は、実機で見て決める【案】。
- 部品の上にポインターを置くと、移動できることを示す形(移動のカーソル)にする。選択した部品には、ハンドル(8つ)を出す。ロック中の部品には、鍵のマークを出す(第6.13章)。
- メニューの項目を、このモード用のものに切り替える(第10章)。「カード」と「スタック」のメニューは、表示しない。「部品」と「テンプレート」のメニューを表示する。
- オブジェクトパレットとインスペクタは、このモードのときだけ表示する。

**プレイモード**

- バナーは出さない。ウィンドウのタイトルは、`<スタック名>`。
- グリッド、部品の枠線のガイド、ハンドルは出さない。部品は、テーマとスタイルで決まる見た目だけを表示する。ウィンドウの背景は、通常の色。
- ステータスバーに、`カード 12 / 300 ・ テンプレート: 名刺管理` のように表示する。テンプレート名をクリックすると、編集モードに入る【案】。

**検索モード**

- カード面の上に、編集モードとは別の色の帯を表示する。例:「検索中 — 条件を入力して Enter キーを押してください」。
- ウィンドウのタイトルは、`<スタック名> — 検索モード`。

**テンプレートのプロパティ(背景など)への入口**

- 編集モードで、部品を何も選択していないときは、インスペクタに、テンプレートのプロパティ(名前、用紙サイズと向き、カード面の大きさ、背景色、背景画像、テーマ、タイトルに使う項目)を表示する。
- メニュー「テンプレート」→「テンプレートのプロパティ…」「背景を設定…」からも開ける。プレイモードや検索モードのときに選んだら、編集モードに切り替えてから開く。

## 5. プレイモード

### 5.1 カードの移動

- 前、次、最初、最後。カードの中に置いたボタン(第6.10章)、メニューの「カード」、ショートカットから操作する。
- メニュー「カード」→「カード番号へ移動…」で、番号を入力して、そのカードへ移動する。
- カードの順序は、`seq` の昇順(データ形式仕様の第8.4章)。
- 検索中は、検索結果の中だけを移動する。

### 5.2 カードの追加・複製・削除

- **新規カード**: 現在のカードの次に、現在のテンプレートで追加する。`seq` は、現在のカードと次のカードの中間値。最後のカードなら、最大の `seq` + 1024。
- **カードを複製**: 現在のカードの値をコピーして、新しいカードを次に追加する(新しい `card_id`)。
- **カードを削除**: 確認ダイアログを出してから、ファイルを、そのボリュームのゴミ箱(Trash)へ移動し、`_trk/original_path` 属性を付ける(Trackerの「元に戻す」用。試作で採用した。実機で確認する)。完全には削除しない。
- **テンプレートを変更**: 現在のカードの `template_id` を、別のテンプレートに変える。値は保持され、新しいテンプレートの部品と合うものだけが表示される。

### 5.3 値の入力

- 入力欄の移動は、Tabキー(進む)とShift+Tab(戻る)。順序は、上から下、左から右(`rect` の `y`、次に `x` の昇順)【案】。
- **入力の途中で、別のカードへ移動したときは、その時点の入力(確定前の文字を含む)を保存してから移動する(必須)**。対象は、カードの移動のすべて(ボタン、メニュー、ショートカット、一覧からの移動、検索結果の中の移動)、モードの切り替え、ウィンドウを閉じること、アプリの終了。保存に失敗したときは、移動せずに、エラーを表示する(入力は残す。第11.2章)。

| 型 | 入力のしかた |
|---|---|
| `text` | 1行(`multiline` が偽)は1行の入力欄、複数行は複数行の入力欄。日本語入力は標準の機能で動くこと(実機で確認する) |
| `number` | 自由に入力できる。入力を終えたとき(フォーカスが外れたとき)に、数値として読めるか検証する。読めなければ、直前の値に戻して警告する。空欄は `null`。表示は `decimals` の桁数に丸めるが、保存する値は入力したままにする【案】。入力中は、保存された値をそのまま表示する |
| `bool` | スイッチ(またはチェックボックス)をクリックして、オンとオフを切り替える。値が `null` のときは、オフとして表示する(保存された値は、操作するまで `null` のまま) |
| `image` | 画像を表示する(`fit` に従う)。ファイルをドロップすると設定する。ダブルクリックで、ファイルを選んで設定する。右クリックのメニューに、「ファイルから設定…」「クリア」を置く |

### 5.4 画像の扱い

- 画像ファイルをドロップしたときは、Translation Kitで読めるか確認し、読めれば `media/image/` にコピーする(元のファイルは変更しない。再エンコードもしない)。`ext` は、元のファイルの拡張子(小文字)にする。拡張子がなければ、中身から判定した形式にする。
- 読めないファイルは、エラーを表示して、値は変えない。
- 画像を差し替えたり、クリアしたりしても、以前のメディアファイルはその場では削除しない(スタック整理で削除する)。
- メディアのファイルが見つからないときは、「画像が見つかりません」と表示する。値(参照)は保持する。
- クリップボードからの貼り付けは、Phase 2 の後半に回してよい。

### 5.5 カードが0枚のとき(仮の新規カード)

- プレイモードでスタックを開いたとき、カードが0枚なら、自動的に、新規カードの入力画面(仮カード。データ形式仕様の第8.6章)を開く。位置の表示は `1 / 1`。
- 利用者が何か入力するまで、カードのファイルは作らない。入力があった時点で保存し、通常のカードにする。
- 何も入力しないまま、スタックを閉じたときは、カードを保存しない。次に開いたときも、同じように、仮の新規カードの入力画面を開く(初回と同じ扱い)。
- 何も入力しないまま、「新規カード」を選んだときは、新しい仮カードを作らず、今の仮カードのままにする。
- 「入力した」とは、値が、テンプレートの初期値と違うものになったこと。入力して初期値に戻した場合は、保存されない。
- 「真っさらなカードから始める」で作ったスタックは、先に編集モードで開く。編集モードを終えて、プレイモードに入ったときに、この動作になる。

## 6. 編集モード(テンプレートの編集)

### 6.1 流れ

部品の置き方は、2通りある。どちらも、置いたあとに、インスペクタで名前などを設定する。

1. **パレットから、部品の種類を選んで置く**: 型が、最初から決まる(第6.2章)。
2. **「枠」を置いて、型を後から設定する**(FileMaker方式): 枠の配置とデザインを先に済ませ、型は後でまとめて設定してもよい。

### 6.2 オブジェクトパレット(ドラッグして置く)

- パレットは、フローティングウィンドウ。上に「選択」ツール、その下に、置ける部品の一覧(アイコンと名前)を並べる。
- 一覧の部品を、カード面へ**ドラッグ&ドロップ**して置く。ドロップした位置に、既定の大きさで部品を作る。ドラッグ中は、置く場所の枠をプレビュー表示する(グリッドにスナップする)。
- 一覧の項目をクリックしてから、カード面をドラッグして、大きさを指定して置くこともできる。
- 置いた部品は選択状態になり、インスペクタの「名前」にフォーカスが移る。
- 既定の名前は、種類の名前と連番(「テキスト1」「数字2」など)。既存の名前と重複しないようにする。

| 項目 | 作る部品(`kind`) | 既定の大きさ【案】 | 備考 |
|---|---|---|---|
| 枠(未設定) | `blank` | 120×24 | 型は、後から設定する |
| テキスト枠 | `text` | 160×24 | |
| 数字枠 | `number` | 96×24 | |
| スイッチ | `bool` | 80×24 | `style` は `switch` |
| 画像枠 | `image` | 120×120 | |
| ラベル | `label` | 80×20 | 文字列は、置いたあとに、その場で入力する |
| ボタン | `button` | 72×28 | 置いたあとに、動作を選ぶ |
| 最初へ | `button`(`card.first`) | 60×28 | 文字列は `◀◀` |
| 前へ | `button`(`card.prev`) | 60×28 | 文字列は `◀` |
| 次へ | `button`(`card.next`) | 60×28 | 文字列は `▶` |
| 最後へ | `button`(`card.last`) | 60×28 | 文字列は `▶▶` |
| ナビゲーションの組(最初・最後つき) | `button`、`button`、`counter`、`button`、`button` | 全体で約 290×28 | 最初、前、位置の表示、次、最後を、一度に置く |
| 位置の表示 | `counter` | 72×20 | |
| ナビゲーションの組 | `button`、`counter`、`button` | 全体で約 210×28 | 前のカード、位置の表示、次のカードを、一度に置く(第6.10章) |

- 画像ファイル(Trackerから)を、編集モードのカード面の空いた場所にドロップしたとき: 「背景にする」「画像枠として置く」の選択肢を出す【案】。

### 6.3 部品の操作

- **選択**: クリックで1つ、Shiftを押しながらクリックで追加・解除。空いている場所をドラッグすると、範囲選択(ラバーバンド)。
- **移動**: ドラッグ、または矢印キー(1ピクセル)。Shift+矢印キーで10ピクセル。
- **リサイズ**: 選択した部品の8つのハンドルをドラッグ。
- **削除**: Deleteキー。確認はせず、取り消し(Alt+Z)できるようにする。ロック中の部品は、削除できない(第6.13章)。
- **複製・コピー・貼り付け**: 新しい `id` を振る。貼り付けた部品は、少しずらして置く。部品の複製は Shift+Alt+D。
- **グリッドへのスナップ**: 8ピクセル。メニューで、オン・オフを切り替える【案】。
- **整列(左、上、等間隔)**: Phase 2 の後半に回してよい。

### 6.4 部品の見た目(編集モード)

| 部品 | 見た目 |
|---|---|
| 未設定の枠(`blank`) | 破線の枠と、「未設定」の文字 |
| 型を設定した枠(`text`、`number`、`bool`、`image`) | 実線の枠と、名前、型を示すアイコンまたは文字(薄い色) |
| ラベル | 文字列をそのまま表示 |
| ボタン | ボタンの見た目。押しても動作しない(選択と移動ができる) |
| 位置の表示 | `1 / 1` のサンプル |

### 6.5 インスペクタ

**部品を1つ選択しているとき**

- 共通: 名前(`label`、`button`、`counter` を除く)、型、位置(`x`、`y`)、大きさ(`w`、`h`)。数値で入力できる。型は、`blank`、`text`、`number`、`bool`、`image` から選ぶ。`label`、`button`、`counter` は、型を変えられない。スタイル、ロック、アイコン、リンク、画像の取得元は、第6.12〜6.14章。
- `text`: 初期値、複数行(チェック)
- `number`: 初期値、小数の桁数(0〜6)
- `bool`: 初期値(オン、オフ、なし)、見た目(スイッチ、チェックボックス)
- `image`: 画像のはめ方(`contain`、`cover`、`stretch`)
- `label`: 文字列
- `button`: ボタンの文字列、動作(一覧から選ぶ。一覧は、データ形式仕様の第7章)
- `counter`: 項目なし

**複数選択しているとき**: 位置と大きさだけ。

**何も選択していないとき**: テンプレートのプロパティ(第6.11章)。

名前の重複は警告する(保存はできる)。

### 6.6 型を変えるとき

型を変えると、カードに入っている値との関係が問題になる。

- 変更の対象の部品に、値を持つカードがなければ、そのまま変える。
- 値を持つカードがあるときは、データ形式仕様の第20.2章の調査(dry run)を実行し、結果をダイアログで示す。例:「このテンプレートを使うカードは 300 枚。そのうち 280 枚の値を変換できます。20 枚は変換できません」
  - **[変換する]**: 変換できた値を書き換える。元に戻せないことを、ダイアログに書く。
  - **[値は変換せず保持する]**: 値は書き換えない。型が合わない値は、孤立値として残る。新しい型で値を入力すると、古い値が上書きされることを、ダイアログに書く。
  - **[キャンセル]**
- 型を `blank` から設定するときは、値を持つカードはないので、確認は不要。
- 値を持つカードがある部品の型を変えたときは、その場でテンプレートを保存する(カードとテンプレートの食い違いを避けるため)。

### 6.7 テンプレートの保存と、編集の終了

- 編集モードの操作は、メモリ上のテンプレートに反映する。取り消し・やり直し(Alt+Z、Shift+Alt+Z)ができる。
- 編集モードを終えるとき(他のモードに切り替えたとき、ウィンドウを閉じるとき)に、テンプレートを保存する(`rev` を1増やす)。
- 型が未設定の枠が残っていたら、「型が未設定の枠が 3 個あります」と通知する。保存はできる。プレイモードでは、未設定の枠は何も表示しない。
- 編集中に、同じスタックの他のウィンドウ(カード面や一覧)があれば、保存したあとに再描画する。

### 6.8 部品の削除と、孤立値

部品を削除しても、カードの値は消えない(孤立値として残る)。削除のとき、値を持つカードがあれば、「この項目の値は 120 枚のカードに残ります。『スタックを整理』で削除できます」と表示する。確認ダイアログではなく、通知にとどめる。

### 6.9 テンプレート全体の操作

メニューの「スタック」→「テンプレートの管理…」から行う。

- 一覧の表示(名前、使用しているカードの数)
- 新規作成(空のテンプレート。または、既存のテンプレートの複製)
- 名前の変更、カード面の大きさの変更
- **タイトルに使う項目**(`title_part`)の指定: 値を持つ部品から選ぶ
- 削除: そのテンプレートを使うカードがあれば、警告する(カードは「テンプレート欠落」の状態になる)。ファイルはゴミ箱へ移動する。

### 6.10 ナビゲーションと、ボタン

- カードの移動(前、次、最初、最後)と、カードの位置の表示は、カードの中に置く部品(`button` と `counter`)で行う。位置、大きさ、文字列は、利用者がデザインする。
- ウィンドウには、ナビゲーション用のボタンも番号の入力欄も置かない(第2.1章)。メニューとショートカットは、常に使える。
- ボタンは、プレイモードで押すと、動作する。編集モードでは、押しても動作せず、選択と移動ができる。検索モードでは、`find.*` と、検索結果の中の移動(`card.first` など)が動く。
- ボタンの有効・無効: 最初のカードでは `card.first` と `card.prev` を、最後のカードでは `card.next` と `card.last` を、無効(グレー)にする。検索していないときは、`find.clear` を無効にする【案】。
- **ナビゲーションの組**: パレットから一度に置ける、前のカードのボタン(`◀`)、位置の表示、次のカードのボタン(`▶`)の3つの部品。置いたあとは、個別の部品として扱う(移動、削除、文字列の変更ができる)。最初へ(`◀◀`)と最後へ(`▶▶`)のボタンは、単独でも、5つの部品の組としても、置ける。
- プリセットには、ナビゲーションの組を含める(データ形式仕様の第19.2章)。空のスタックには含めない(パレットから置く)。

### 6.11 テンプレートの背景

- 背景色と背景画像は、テンプレートのプロパティ。次のどちらからでも設定できる。
  - 編集モードで、何も選択せずに、インスペクタを使う。
  - メニュー「テンプレート」→「背景を設定…」。
- **背景色**: 色を選ぶ。「システムの色に戻す」で、解除する。
- **背景画像**: 「ファイルを選ぶ…」、またはファイルのドロップで設定する。「クリア」で、解除する。読めないファイルは、エラーを表示して、設定を変えない。
- **はめ方**: 「全体に合わせる(`cover`)」「収める(`contain`)」「引き伸ばす(`stretch`)」「並べる(`tile`)」から選ぶ。
- 設定すると、カード面にすぐ反映する。プレイモードと検索モードでも、背景を表示する。
- 背景画像のファイルは、`media/image/` に置く(データ形式仕様の第9章)。差し替えやクリアをしても、以前のファイルは、その場では削除しない(スタック整理で削除する)。
- カードごとに背景を変える機能は、まだ設けない(第15章)。

### 6.12 部品のスタイル(枠線、背景、文字)

インスペクタの「スタイル」の欄で、選択した部品の見た目を設定する(データ形式仕様の `style`)。

- **枠線**: 表示する・しない(チェック)、太さ(0〜16)、色。
- **枠内の背景**: 色、または透明。
- **文字**: フォント(ファミリーとスタイルの一覧)、サイズ(6〜96)、色。
- 「テーマの値に戻す」: 設定した値を取り消して、テーマの値を使う。
- 設定していない項目には、現在のテーマの値が表示される(薄い色で、設定済みの値と区別する)。
- 複数の部品を選択しているときは、スタイルを、一度に変えられる。
- 設定した色は、「最近使った色」として、色の選択に残る【案】。

### 6.13 ロックとロック解除

- ロックすると、その部品の移動、大きさの変更、設定の変更、削除ができなくなる(データ形式仕様の `locked`)。
- 切り替え: メニュー「部品」→「ロック」「ロック解除」(Alt+K、Shift+Alt+K)、インスペクタのチェック、右クリックのメニュー。複数の部品を、まとめて切り替えられる。メニュー「部品」に、「すべてをロック」「すべてのロックを解除」も置く。
- ロック中の部品: 選択はできる。枠に鍵のマークを出し、ハンドルは出さない。インスペクタは、ロックの欄以外をグレーにする。移動やリサイズのドラッグは受け付けず、ポインターを、禁止の形にする。
- プレイモードでの値の入力と、ボタンの動作には、影響しない。

### 6.14 アイコンとリンク

- **アイコン**: `button` と `label` に、アイコンを付けられる。インスペクタの「アイコン」の欄の [選ぶ…] から、アイコン選択ダイアログ(テーマ仕様の第8.4章)を開く。大きさ(12〜128)と、文字列との位置(左、上)を選べる。「クリア」で外す。
- **リンク**: `image`、`label`、`button` に、リンク(URL)を付けられる。インスペクタの「リンク」の欄で、「固定のURL」(URLを入力)か、「項目から」(同じカードのテキスト項目を選ぶ)を選ぶ。リンクの規則は、入出力仕様の第2章。
- **画像の取得元**: `image` に、「取得元の項目」(URLを持つテキスト項目)と、サムネイルの大きさを設定できる(入出力仕様の第3.6章)。
- リンクを持つ部品は、プレイモードで、ポインターが手の形になる。

### 6.15 用紙サイズとテーマ

- **用紙サイズと向き**: テンプレートのプロパティ、またはメニュー「テンプレート」→「用紙サイズと向き…」で変える。選択肢は、第3.4章と同じ。向きを変えると、幅と高さが入れ替わる。部品の位置は変えず、はみ出す部品があれば知らせる。
- **テーマ**: テンプレートのプロパティの「テーマ」の一覧(同梱のテーマ、利用者のテーマ、このスタックのテーマ)から選ぶ(テーマ仕様の第3章)。「このスタックのすべてのテンプレートに適用」のボタンもある。選ぶとすぐ、カード面に反映する。

## 7. 一覧ビュー

- 表形式でカードを表示する。列は、テンプレートの値を持つ部品(列の見出しは `name`)。行は、カード。
- スタックに複数のテンプレートがあるときは、一覧の上部で、どのテンプレートのカードを表示するかを選ぶ【案】。
- 行をダブルクリックすると、そのカードをスタックウィンドウで開く。
- 並べ替え: 列の見出しをクリックすると、昇順・降順を切り替える。`number` は数値として、`text` は文字列として並べ替える。`text` の並べ替えは、バイト順(試作)。日本語の読み順にするかは、第15章。
- 簡易検索: 一覧の上部に検索ボックスを置く。入力した文字列を、すべての `text` 部品から部分一致(大文字小文字を区別しない)で探し、一致したカードに絞り込む。
- `image` の列は、「あり」「なし」を表示する(サムネイルは後続)。`bool` の列は、オンのときに ✓ を表示する。
- 列の表示・非表示、列の幅は、アプリの設定として記憶する(スタックのフォルダには入れない)【案】。
- 10万枚のスタックでも、スクロールが滑らかであること。表示範囲の行だけを描画する(全行分の項目を生成しない)。実装方法は実装者が選ぶ。

## 8. 検索モード

- カード面と同じレイアウトで、検索の条件を入力する(例による検索)。
- 条件の解釈:

| 型 | 解釈 |
|---|---|
| `text` | 入力した文字列を含む(部分一致)。大文字小文字は区別しない(ASCII と全角英字だけを同一視する) |
| `number` | `10` は一致、`10..20` は範囲、`>=100`、`<=100`、`>100`、`<100` は比較 |
| `bool` | 「オン」「オフ」「指定なし」の3択(既定は、指定なし) |
| `image` | 条件にしない(Phase 2) |

- 複数の枠に条件を入れたときは、すべてを満たす(AND)。
- 実行は、Enterキー、または「検索」ボタン。
- 結果は、カードの集合(検索結果)になる。カード面のナビゲーションと一覧は、結果の中だけを対象にする。ステータスバーに、`検索結果 12 / 300` と表示する。
- 「すべて表示」で、検索を解除する。
- 実装は、カードの集合を返す抽象インターフェース(例: `CardQuery`)の裏に置く。Phase 2 では、メモリ上の絞り込みで実装し、Phase 3 で、BFSのクエリに置き換えられるようにする。

## 9. スタックの管理

メニューの「スタック」から行う。

- **スタックを整理…**: データ形式仕様の第13章の調査(dry run)を実行し、結果をダイアログで示す。
  - 例:「孤立した値: 12 枚のカードに 15 個。使われていない画像: 3 個。一時ファイル: 0 個」
  - 読めないカードやテンプレートがあるときは、画像ファイルは削除されないことを、ダイアログに書く(データ形式仕様の第13章)。
  - [整理する] [キャンセル]。「元に戻せません」と書く。
- **問題リスト…**: スタックを開いたときに見つかった問題(壊れたファイル、重複したID、テンプレート欠落など)を一覧する。問題があれば、スタックを開いたときに、ステータスバーに「問題が 2 件あります」と通知する(ダイアログで止めない)。
- **スタックの設定…**: スタックのタイトルの変更。
- **ログを開く**: そのスタックのログのフォルダを、Trackerで開く(データ形式仕様の第21.9章)。

## 10. メニューとショートカット【案】

ショートカットは、Haikuの標準(Altキー)に合わせる。標準のショートカットと衝突しないか、実機で確認する。

**メニューの項目は、モードによって切り替える(必須)**。使えない項目をグレーにするだけでなく、そのモードに関係のないメニューは、表示しない。

### 10.1 プレイモード

| メニュー | 項目(ショートカット) |
|---|---|
| ファイル | 新規スタック…(Shift+Alt+N)、CSVから新規スタックを作る…、スタックを開く…(Alt+O)、最近使ったスタック、現在のカードをPDFで保存…、閉じる(Alt+W)、終了(Alt+Q) |
| 編集 | 取り消し(Alt+Z)、やり直し(Shift+Alt+Z)、切り取り(Alt+X)、コピー(Alt+C)、貼り付け(Alt+V)、すべて選択(Alt+A) |
| カード | 新規カード(Alt+N)、カードを複製(Alt+D)、カードを削除、前のカード(Alt+←)、次のカード(Alt+→)、最初のカード(Alt+↑)、最後のカード(Alt+↓)、カード番号へ移動…(Alt+G)【案】、テンプレートを変更… |
| モード | プレイモード(Alt+B)、編集モード(Alt+L)、検索モード(Alt+F) |
| 表示 | 一覧を表示(Alt+T)、拡大(Alt++)、縮小(Alt+-)、等倍(Alt+0)、ウィンドウに合わせる |
| スタック | CSVを読み込む…、画像を取得…、スタックを整理…、問題リスト…、テンプレートの管理…、スタックの設定…、ログを開く |
| ヘルプ | このアプリについて |

### 10.2 編集モード

| メニュー | 項目(ショートカット) |
|---|---|
| ファイル | 新規スタック…、スタックを開く…、閉じる、終了 |

## 11. 保存とエラー処理

### 11.1 自動保存

- カード: 次のいずれかのときに保存する。
  - カードを移動したとき
  - 入力が一定時間(2秒【案】)止まったとき
  - ウィンドウを閉じたとき
  - アプリを終了するとき
- テンプレート: 編集モードを終えるときに保存する(第6.7章)。
- 保存は、データ形式仕様の第12章のアトミック保存の手順で行う。

### 11.2 保存に失敗したとき

- エラーを表示する(`BAlert`)。入力した値はメモリに保持し、再試行できるようにする。
- 失敗している間に、ウィンドウを閉じる、アプリを終了するときは、「保存されていない変更があります」と確認する。

### 11.3 外部で変更されたとき

- 保存の前に、データ形式仕様の第12章の競合の検出で、ファイルが外部で変更されたと分かったら、確認する。
  - **[上書きする]**: メモリ上の内容を保存する。
  - **[読み直す]**: ファイルの内容を読み直し、メモリ上の編集は破棄する。

### 11.4 ログ

- ユーザーの動作のログを記録する(データ形式仕様の第21章)。
- UIが記録するのは、アプリの起動と終了、スタックを閉じたこと、検索の実行(条件の数と結果の件数だけ。条件の文字列は記録しない)。モードの切り替え、カードの移動、一覧の並べ替え、ボタンの動作は、`debug` として記録する。
- カードの作成・削除など、データが変わる操作は、`core` が記録する。UIで重複して記録しない。

## 12. 受け入れ基準(手動テスト)

Phase 2 は、次のシナリオが、実機またはVMのHaikuで通れば完了とする。

1. 引数なしで起動し、スタートウィンドウから「真っさらなカードから始める」を選ぶと、編集モードで空のスタックが開く。
2. 枠を3つ置き、名前と型(テキスト、数字、画像)を設定し、プレイモードに切り替えると、入力できる。
3. プレイモードで、各項目に値を入力し、新規カードを追加し、前後に移動しても、値が保持される。アプリを終了して開き直しても、残っている。
4. スタートウィンドウから「テンプレートから始める」を選び、プリセット(住所録など)でスタックを作ると、プレビューどおりのカード面が開く。
5. `.bdbm` をダブルクリックすると、そのスタックが開く。
6. 編集モードで、部品を移動・リサイズ・削除・複製・取り消しできる。
7. 型の変更で、変換の確認ダイアログが出て、「変換する」と「値は変換せず保持する」の両方が期待どおり動く。
8. 部品を削除しても、カードの値は残り、「スタックを整理」で消える。
9. 画像ファイルをドロップして設定できる。読めないファイルでは、エラーが出て値は変わらない。
10. 一覧ビューで、並べ替えと簡易検索ができ、行のダブルクリックでカードが開く。
11. 検索モードで、数値の範囲(`10..20`)と文字列で絞り込め、「すべて表示」で解除できる。
12. カードを削除すると、ゴミ箱へ移動する。
13. 保存に失敗させたとき(書き込めない場所など)に、エラーが出て、入力した値が失われない。
14. 外部でカードのファイルを書き換えたあとに保存すると、確認ダイアログが出る。
15. 10万枚のスタックで、一覧ビューのスクロールと並べ替えが、実用的な速さで動く(計測して報告する)。
16. 操作したあとに、ログが記録される(カードの追加・削除、型の変更、整理、検索)。ログに、入力した値が含まれていない。メニューの「ログを開く」で、ログのフォルダが開く。
17. パレットから、各種類の部品(テキスト枠、数字枠、スイッチ、画像枠、ラベル、ボタン、位置の表示、ナビゲーションの組)を、ドラッグして置ける。置いた直後に、インスペクタで名前を入力できる。
18. カードの中に置いたボタンと位置の表示で、カードを移動できる。ウィンドウに、ナビゲーション用のボタンがない。
19. 背景色と背景画像を設定でき、プレイモードと検索モードでも表示される。背景画像をクリアできる。
20. 編集モードとプレイモードを、ひと目で区別できる(バナー、ウィンドウのタイトル、ウィンドウの背景色、グリッド、値が表示されないこと、メニューの項目)。
21. システムの言語が日本語のときは日本語、日本語以外(例: ドイツ語)のときは英語で表示される。プリセットも、同じ言語になる。
22. スイッチ(`bool`)を入力でき、検索の3択と、一覧の ✓ が動く。
23. 新規作成で、用紙サイズ(画面用の標準、A4、A5、A6、B4、B5、B6、ハガキ、自由)と向きを選べ、カード面の大きさに反映される。あとからテンプレートのプロパティで変えられる。
24. 初回の起動で、サンプルスタックが「最近使ったスタック」に並んでいる。サンプルを開くと、コピーが作られ、編集できる。2回目からは、コピーが開く。
25. カードが0枚のスタックを開くと、新規カードの入力画面が開く。何も入力せずに閉じると、カードは保存されず、次に開いても、同じ画面が開く。入力すると保存される。
26. 入力の途中で、別のカードへ移動すると、その時点の入力が保存されている(ボタン、メニュー、一覧からの移動のそれぞれで)。
27. パレットから、最初へ・最後へのボタンを置いて、動作する。
28. 部品のスタイル(枠線の表示・太さ・色、枠内の背景色、フォント、サイズ、文字の色)を変えられ、保存と再読み込みで保たれる。
29. 部品をロックすると、移動、リサイズ、設定の変更、削除ができない。ロックを解除すると、できる。
30. ボタンにアイコンを付けられる。スタックを別の場所にコピーしても、アイコンが表示される。
31. リンク付きの画像やラベルをクリックすると、確認のあと、ブラウザでURLが開く。`http`、`https`、`mailto` 以外は開かない。
32. プレイモードと編集モードで、メニューの項目が切り替わる。画面の見た目(バナー、グリッド、ウィンドウの背景色)でも区別できる。
33. PDF保存: 現在のカード、複数の選択したカード、一覧が、PDFとして保存できる。日本語が文字化けしない(入出力仕様の第5章)。
34. CSVの取り込みウィザードで、CSVからスタックを作れる(列の割り当て、画像のサムネイル、リンク。入出力仕様の第5章)。
35. テーマを切り替えると(BeOS、Haiku、NeXTSTEP、Mac OS、Windows 95)、カード面の見た目が変わる。テーマのないスタックを開くと、既定のテーマになる。

## 14. UIの言語とアプリの識別

### 14.1 UIの言語

- 対応する言語は、日本語と英語。
- **決め方**: システムの優先言語のうち、最優先のものが日本語(`ja`)なら、日本語で表示する。それ以外は、英語で表示する。優先言語を取得できないときは、日本語にする【案】。
- 言語は、起動時に1回決める。実行中は変えない。
- **対象**: メニュー、ダイアログ、ステータスバー、パレット、インスペクタ、エラーメッセージ、部品の既定の名前(「テキスト1」は、英語では「Text 1」)、プリセット。
- **対象外**: ログ(英語のイベント名と、種別のコードだけを記録する)。スタックの中のデータ(カードの値、テンプレートの名前、部品の表示名)。
- **プリセット**: 日本語のとき `presets/ja/`、それ以外は `presets/en/` を使う。英語のプリセット(住所録は `Address Book`、書籍管理は `Books`、名刺管理は `Business Cards`)は、これから作る。部品の `name` や `label`、`button` の文字列も、英語にする。
- **実装**: 文言は、1か所に集約する(試作の `Strings.h`)。HaikuのLocale Kitのカタログ(`BCatalog`)を使うことを推奨する【案】。言語を追加しやすい形にする。
- 設定での手動切り替えは、第15章。

### 14.2 アプリの識別

- アプリのシグネチャ: `application/x-vnd.bdb-app`【案】
- MIMEタイプ: データ形式仕様の第3章のとおり。
- 設定とログの場所: `~/config/settings/BDB/`
- hpkg でインストールしたときの場所: `/boot/system/apps/BDB/`
